## Verification

A row is kept only when all of the following hold:

1. The interpreter parses it (`run_tests`, backend `interp`). `parse_error` and `unsupported` are drops. A step-cap timeout is a failed test.
2. `CORRECT` passes every test.
3. A class row fails at least one test and `holds(op_id)` is true. `holds` is `holds_dsa` for a DSA op_id and `holds_main` otherwise. `oth_*` is always false.
4. `OTHER` fails at least one test and no class predicate holds.
5. `d05_unreachable_base` also needs an odd scalar test argument.
6. Two-bug rows (bounded sample, source E) need both predicates and must fail a test that each single mutant also fails.

Rows that were built as a misconception but pass every test are written to `ml/data/passes_by_luck.jsonl` with `verified.passes_by_luck` true. They are not in `dataset.jsonl` and they are not part of the row count above.

## Known biases

- Every training row is an author-written template or a mechanical edit of one. No real learner programs are in this file.
- Style variety is a fixed list (a few identifier pools, eight comment lines, K&R / Allman / no braces). That is one cohort's habits, repeated.
- Operators with no bank site (`m02_update_in_branch`, `m04_int_literal`, `m06_while_assign`, `d08_array_eq`) contribute no rows. D-classes and a few M-classes have too few sites to hit 250–550 rows at 15 per problem, so their cap is raised and those templates are over-represented. `n_unique_hash` is the fairer count.
- Held-out problems (P04, P09, P13, Q04, Q09, Q16) are in the file with `split: holdout_problem`. Training must drop that split.
- `op_variant` equals `op_id`.

## ITSP

This file does not contain the ITSP slice. The plan treats ITSP as an evaluation-only set: cite the FSE 2017 Prutor paper and do not redistribute student programs. The upstream repository also carries an MIT licence (see notes/X1.md); either reading still keeps those programs out of training and out of this card's row count.

## R protocol

R-blind (40 items, written without the operator list) and R-team (30 items) are not in this file. A second rater labels each item from the code alone; the report for that set is percent agreement and Cohen's κ. Disagreements keep both raw labels. κ is not computed here because this corpus has no second rater: the label is the operator that built the row.
