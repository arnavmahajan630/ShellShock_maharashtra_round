# R1 — Verified fixer, counterexample search, fix-probe features

## Built

- `ml/learner/fixer.py`: `repair(problem, code, cls)` and `probe(...)`. For one class, the §7.3 edits run in table order, at most five, each on a fresh syntax tree reprinted with `pycparser.c_generator`. The first candidate that passes `ml.runner.run_tests` is returned as `{kind: "minimal", code, changed_lines, rule, verified: true}`. If none passes, a correct variant that is not the learner's text is returned as `{kind: "reference", ...}`. Results are cached by sha256 of the source, the problem id and the class. A class stops at the first full pass.
- `ml/learner/counterexample.py`: `search(problem, code, cls=None)` returns `{input, intended, yours, effect_diff}` for the smallest pool input on which the learner and `correct_variants[0]` disagree. The pool is n in {1, 2, 3}, the arrays and DSA pools from §7.2, the problem's own tests, and recursion n in {0, 1, 2, 3, 10}.
- `ml/features/fix_feats.py`: `fix_features(problem, code, classes)` fills `f_fix_<class>` and `f_fixgain_<class>` only for the classes it is given (the top-3). Other group-F names are absent, not 0. These are not training-matrix columns.
- `ml/learner/__init__.py` also exports `fixer` and `counterexample`. `knowledge` and `state_machine` are unchanged.
- `tests/R1/test_r1.py`. `pytest tests/R1 -q` — 3 passed.

## Repair rate

One mutant per operator: the first site on the first variant that has one. A mutant is `apply(op, correct_variant, site)` from `ops_main` / `ops_dsa`. Holdout is any site on P04, P09, P13, Q04, Q09, Q16, whether or not `allowed_ops` lists the operator. Operators with no holdout site are measured on a train problem and are not in the 80% denominator.

| Set | Rate |
|---|---|
| Holdout (the bar) | **100% (28/28)** minimal, and the repaired code passes the problem tests |
| Train, operators with no holdout site | 68.4% (13/19) |

No holdout class missed the bar. Classes with no holdout mutant at all, measured only on train: **D02, D03, D04, D08**. Their train mutants were repaired (binary-search window, swap and rotate, one-pass sort, `"a"` back to `'a'`).

Train misses, listed so they do not sit inside the holdout rate:

| Operator | Why the listed edits do not restore it |
|---|---|
| `m01_countdown_ge0` | The table tightens `<=` to `<` and loosens `<` to `<=`. A countdown `>=` is neither. |
| `amb_pair_bound` | The mutant widens `j < n - 1` to `j < n`. The table only edits `n - 1` toward `n`, the other direction. |
| `m08_mirror` | `a[n - i]` is not the bare `a[n]` the table rewrites to `a[n - 1]`. |
| `m01_half_bound` | `i < n / 2` became `i < n`. Nothing in the table puts the `/ 2` back. |
| `m02_pointer_stuck` | The increment was deleted inside one branch. Appending `i++` on a loop that still updates the other pointer is a different bug, and the table's "move the update out of the if" is the opposite direction. |
| `d05_unreachable_base` | The step is `n - 2` as well as the base. Inserting `if (n <= 0) return B` does not restore `n - 1`, so factorial stays wrong. |

No bank site anywhere: `m04_int_literal`, `m06_while_assign`, `d08_array_eq`. The char-by-char rewrite for an array-name `==` is implemented and falls through to the reference variant when it does not apply. It was not measured.

`m08_onebased` on P04 is repaired by `start 1 to 0` while the bound stays `<= n`. That is the first candidate that passes. The extra iteration reads one past the end; on this problem's tests that cell is not over the limit, so the count still matches. The spec says to accept that candidate.

`m02_wrong_var` is repaired by pointing the progress `++` back at the loop variable. Appending a second `i++` next to `n++` never finishes, because `n` grows with `i`. A `++` nested in an `if` (the counter) is left alone, so `m02_drop_update` still gets a real appended `i++`.

## Text edits vs tree edits

No coordinate text edit. Every candidate is a syntax-tree change reprinted with `CGenerator`.

The stray semicolon (M07) parses as an `EmptyStatement`. The fixer moves the following statement back into the `if` / `for` / `while`. Deleting the semicolon is that tree edit, not a splice of the source text.

A few nodes are built by parsing a one-line template (`int t = a[0]`, `for (int p = 0; p < n - 1; p++)`, `if (n <= 0) return 0`) and grafting the node in. The learner's function is still edited as a tree.

## What is faked or skipped

- Belief answers are recognised only for **M04** (the intended output is a non-integral float and the learner's value differs: the belief is that quotient), **M10** (the printed text parses as the intended value), and **D01** (the searched-for value sits at index 1 and the reference says it is present). Every other class returns the smallest differing input. The belief sentence in §7.2 is not simulated for them.
- Group F for classes you do not pass in is omitted, not stored as 0.
- The cache is in-process only. It is not shared across processes.
- §7.1 policy and §7.4 timeline are package R2. Not built.
- Two-bug composition (`fix(top1)` then `fix(top2)`) is not here. `probe` runs one class.
- A candidate that fails to build is skipped. It does not count toward the five.
