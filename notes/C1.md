# C1 — Main-class operators

## Built

- `ml/generate/ops_main.py`: every main-game operator in 03 §3.5.1 from `m01_le` through `oth_drop_stmt`, plus `u1_chained` and `u2_or_chain` (`test_only=True`).
- `ml/generate/predicates_main.py`: `holds(op_id, code)` on the mutant's syntax tree.
- `tests/C1/test_ops_main.py`. `pytest tests/C1` — 41 passed.

C3 imports `Op`, `all_ops`, `sites`, `apply` from `ops_main` and `holds` from `predicates_main`. `sites(op, code)` is a list of ints. `apply(op, code, site)` parses again and reprints with `pycparser.c_generator.CGenerator`, so one site cannot leak into the next. An operator applies to a problem when `fnmatch` matches `op_id` against `allowed_ops`.

DSA-surface ops (`amb_pair_bound`, `m08_mirror`, `m01_half_bound`, `m02_pointer_stuck`, `m10_print_bool`) and D01–D08 are not here.

## No bank site

These three have no `correct_variants` entry under a matching `allowed_ops` glob. The test covers each with a hand-written snippet of the catalogue's "Applies when" shape. That snippet parses, fails a test, and (for the two M operators) satisfies `holds`.

| op_id | Why the bank has no site |
|---|---|
| `m02_update_in_branch` | Needs a `while` that already contains an `if`. P04 cv2 is that shape, but P04's `allowed_ops` has no `m02_*`. P01, P02, P05, P06 do not put an `if` in the `while`. |
| `m04_int_literal` | No `/ 2.0` or `* 100.0` in a correct variant. P13's `100` is already an int; the float-ness comes from a cast (`m04_drop_cast` / `m04_cast_late`). |
| `m06_while_assign` | No `while` condition uses `==` or `!=`. |

## Decisions

- **M03 declaration.** `m03_decl_in_loop` copies `int t = <const>;` into the loop and leaves the outer declaration. Moving it would make `return t` refer to an undeclared name (the interpreter rejects that). The inner name shadows the outer one, so the running total resets every pass and the returned variable stays at its original value.
- **M07 semicolon.** The old body is spliced out as the next statement (`if (c); { ... }`). A `for (int i = …)` declaration is hoisted into the enclosing block first, so the spliced body can still name `i`. `m02_drop_update` turns a sole body into `{}`, not `;`, so it does not also become M07.
- **M02 progress.** `m02_drop_update` deletes the update of the condition variable (for-update, else the last body statement that writes it), including `--` and `+=`, not only `i++`.
- **M01 vs a correct count.** `holds("m01_le")` and `holds("m01_while_le")` require init `0` and `<= n`. `holds("m01_start1_count")` requires init `1` and a bound that is still `<`. The correct count `i = 1; i <= n` matches neither. `amb_le_array` is `<= n` with an array index and init not 1. `amb_start1_array` is init 1, bound still `<`, and an array index. `m08_onebased` is both changes at once (init 1 and `<=`).
- **M05.** All three `m05_drop_init_*` operators use one predicate: a scalar is read before it is assigned. `int t; t = 0;` (assign before use) does not match.
- **M06.** `==` / `!=` becomes `=` only when one side is a variable, so the file still parses. `42 == code` becomes `code = 42`.
- **M10.** `return e` becomes `printf("%d", e)`, including when `e` is float, as the catalogue writes it. `m10_printf_return0` skips a `return` that is already `0`, which would not change the value.
- **OTHER constants.** A multi-digit literal is reversed (`42` → `24`); a single digit drops by one (`7` → `6`). `0`, `1`, loop-header literals, and array indexes are left alone. `holds("oth_*")` is always false. The bank mutant each `oth_*` test keeps does not satisfy an M predicate.
- **U1 / U2.** Test only. `lo < x && x < hi` becomes the C reading `(lo < x) < hi`. `c == 42 || c == 7` becomes `c == 42 || 7`. They parse. They are not required to fail an M predicate.
