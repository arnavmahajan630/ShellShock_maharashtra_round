# A1 — C interpreter (`ml/c_interp/`)

## Built

- `preprocess.py`: smart quotes and other non-ASCII punctuation normalised; `//` and `/* */` comments replaced by spaces with every newline kept; `#include` lines blanked; `#define NAME value` applied as text substitution (not inside string or char literals); every other `#` line rejected. Lines are never added or removed, so every `line` in a trace is the learner's own line. `normalise` and `strip_comments` are plain functions; the gate can reuse them for G1, G2 and G8.
- `values.py`: value helpers, literal parsing, `printf` formatting.
- `interp.py`: `Program(code, forbid)`. Parses with pycparser 3.0, rejects the constructs of 03 §2.1, then turns each tree node into a Python closure (one builder method per node type) and runs those. Int and float paths are chosen while walking the tree because C types are static.
- `harness.py`:
  - `run_tests(problem, code, sample_only=False)` → `schemas.RunResult` shape.
  - `trace(problem, code, test_index=None)` → `schemas.Trace` shape.
  - Extra, not in the contract: `check(code, problem=None)` → `{"status": "ok"}` or `{"status", "line", "reason", "construct"}`. `Trace` and `RunResult` have no place for the parse-error text, and gate messages G3a / G4 / G4b / G5 need a line, a reason or a construct. `construct` is a key of `subset.REJECTED` when one applies.
  - Parsed files are cached by source text (256 entries), so `run_tests` followed by `trace` on the same code parses once.
- Everything in the 03 §2.2 table, including the string rows (char arrays, string literals, `%s`, `strlen`, `==` on a literal or on two array names). Strings were **not** dropped.
- `tests/A1/`: 210 tests. One group per row of 03 §2.2 (`test_semantics.py`), the 03 §2.5 "v3 extra" list (`test_v3_extra.py`), the subset and the rejected constructs (`test_subset.py`), the preprocessor, the harness shapes, the step rules, a gcc differential and a timing check.

## Sample traces: what agrees and what differs

`trace()` on `P03_LE`, `P03_NO_UPDATE` and `Q17_OK` validates against `schemas.Trace` and equals the committed sample trace on `status`, `returned`, `printed`, `events`, `loop_iters`, `branch`, `effects_count` and `max_depth`. The recorded steps are equal too, step for step (for `P03_NO_UPDATE`, the first 60). `P11_SEMI` equals the hand simulation in `build.py` on steps, events and counters.

Three differences, none in the fields listed in the task:

1. **`per_test[].branch` always has both keys.** The samples drop a side that is zero (`{"B2": {"true": 1}}`); the interpreter writes `{"B2": {"true": 1, "false": 0}}`, as 03 §2.2 shows it. A reader that uses `.get(side, 0)` works with both. An `if` that did not run in a test is absent from that test's `branch`, and a loop with no pass is absent from `loop_iters`, as in the samples.
2. **`p03_no_update_step_cap`** keeps 60 steps in the sample (W0 note); the interpreter keeps 2,000 (`truncated: true`).
3. **Q06 swap without temp** (hand simulation in `build.py`, used for the server fixtures, not one of the three sample traces): the interpreter adds one last step at the closing brace of the `void` function, carrying `ret:bubble_sort:1:`. See decision 3 below. So `effects_count` gains `ret: 4` (one per test). The other steps, the other counters and the `tests` object are equal.

## Decisions made where 03 and W0 are silent

These are what other packages see.

1. **What counts as an executed statement** (step cap): every recorded step except the two kinds in 3 and 4. A `while` / `do-while` test, and a `for` init, test and update, each count as one. This is what the sample step-cap trace does (2,499 passes per test). A `for` with no condition still counts one test step per pass, so `for (;;);` stops at the cap. The cap event sits on the line of the statement that would have been number 5,001.
2. **A declaration with several names** (`int low = 0, high = n - 1;`) is one step. Two declarations on one line are two steps.
3. **Closing step of a function that falls off its end.** One step is recorded at the line of the function's closing brace, with the `ret` effect (`ret:f:2:` for `void`, the value field is empty) and, for a non-void function, the `missing_return` event and `ret:f:1:-858993460`. Without it a `void` function would have no `ret` and an empty function no step at all, so `call` / `ret` would not pair up. It is not counted as an executed statement.
4. **Early step at a call.** When a statement has already produced effects and then calls a user function, those effects are recorded as a step at once (same line, same frame), then the callee's steps follow, then the statement's own final step. Without this, effects come out of order: for `int f(int n) { return n <= 1 ? 1 : n * f(n - 1); }` the trace would read call 3, ret 3, call 2, ret 2, call 1, ret 1, and a missing base case would show no `call` at all before the depth cap. With it, `Q17_OK` and all sample traces are unchanged. A reader that counts steps per line will see the calling line twice in these cases. Not counted as an executed statement.
5. **A halt records one last step** (step cap, depth cap, division by zero) on the line where it happened, carrying the event, in the innermost frame.
6. **Cell effects only for the test's own arrays.** `read_cell`, `read_void`, `write_cell` and `compare` are produced only for arrays the harness passed in as arguments, including when they are handed on to helpers or recursive calls. Local arrays produce events (`oob_read`, `oob_write`, `uninit_read`) but no effects, because effects carry no array name and W0 says the app rebuilds the array from the test's args plus `write_cell`. A problem with two array arguments would mix their indexes; no planned problem has two.
7. **`compare:i:j`** needs both sides of a relational operator to be cells of the same test array. It is also produced when an index is out of bounds (next to the `read_void`).
8. **`call` args:** scalars as values, arrays as the callee's parameter name (`call:total_energy:1:cells,3`). No args gives an empty field (`call:f:2:`). Floats use up to 6 significant digits (`ret:avg:1:2.33333`).
9. **`vars`** lists the scalar parameters, then every scalar local of the function in declaration order, from the first step on; a local not declared yet is `null` (as in the samples). When a name is declared twice in one function, the live one is shown. A local keeps its last value after its block ends. Globals and arrays are not in `vars`. `char` values are numbers.
10. **Event details:** `empty_body` fires each time the `if` or loop statement is reached (once per loop, not once per pass); an empty `else ;` reports `kind: "if"`. `assign_in_cond` fires only when the whole condition is a plain `=` assignment (`if ((y = x) == 5)` does not). `intdiv` fires for every int / int division, also when the remainder is zero. `into_float` is true when the quotient is converted to float by its user: assigned to or initialising a float, returned from a float function, passed to a float parameter, cast with `(float)` / `(double)`, or combined with a float operand; it passes through int `+ - * /`, unary minus and `?:` (`float x = a / b + 1;` is true), and stops at `(int)`. `uninit_read` on an array cell has `var` = the array name plus `idx`. `discarded_call_value` fires for a statement that is a call to any non-void user function, before the call runs. `depth_cap_hit.last_args` is the list of arguments of the call that was refused.
11. **Uninitialised reads** fire on every read. A declaration without an initialiser inside a loop is unset again on every pass.
12. **Division by zero** halts for `/` and `%`, and also for float division (C would give infinity; JSON cannot carry it).
13. **Statuses.** `unsupported`: a construct of 03 §2.1 "Rejected", a `#` line other than `#include` / `#define NAME value`, a forbidden `strlen`, a `printf` format outside the list, `static`, `typedef`, `enum`. `parse_error`: anything gcc would refuse to build: syntax errors, undeclared names, undefined functions, wrong argument count or kind, and an entry function that is missing or does not fit the tests' args. On both, `trace` returns no steps and one `per_test` entry per test with that status, and `run_tests` returns every test with `got: {}` and `pass: false`.
14. **Trace `status` and `RunResult.status`** are the first status that is not `ok`, in test order (as in `build.py`). `returned` and `printed` on the trace are the shown test's.
15. **`got`** has the same keys as the test's `expect` (`max_depth_le` holds the depth reached; an effect name holds its count; `array0` is a string when the expected value is a string). When a test did not end `ok`, `got` also has `status`.
16. **`printed`** is compared exactly. Ints compare exactly, anything with a float within 1e-3.
17. **Test args:** a list becomes an array of the parameter's element type, a `str` becomes a `char[]` with a terminator, a one-character `str` for a `char` parameter becomes its code. The problem's own args are never changed.
18. **Entry function** is the name in `problem["signature"]`, else `problem["name"]`. Other functions in the file, including a `main`, are allowed and ignored.
19. **Beyond the list in 03 §2.1, accepted because they cost nothing:** global variables (reset before every test, zero when not initialised), `long` / `short` / `unsigned` (all 32-bit signed ints), `& | ^ << >> ~`, `sizeof`, the comma operator, variable-length local arrays, more `printf` conversions (`%u %x %o %e %g`, width and flags).

## Known differences from gcc

- `char` is a plain int: it is not cut to 8 bits. `char c = 'a'; c = c * 2;` gives 194 here and -62 in gcc. 03 §2.1 says "char (as int)".
- `float` and `double` are both Python floats (64-bit). Results agree with gcc well inside the 1e-3 tolerance; a `%f` of a large `float` can differ in the last digits.
- `unsigned` arithmetic is signed. `long long` is 32-bit.
- A `printf` conversion that does not fit its argument is undefined in C. Here it is fixed: `%d` with a float prints the low 32 bits of the double, `%f` with an int prints `0.000000`, a missing argument prints `-858993460`, `%s` with a non-array prints `(null)`.
- A call to a function defined later in the file needs no prototype.
- `#include` lines are blanked without being checked, so a malformed one (`#include stdio.h>`) that gcc refuses is accepted here.

## Skipped

- `scanf` with an input queue (03 marks it Strong, ITSP only) and `switch` ("add only if time"): both stay rejected.
- `<stdbool.h>` (`bool`, `true`, `false`) is not supported: pycparser reports a parse error.
- No cap on the number of events. A loop that makes two events per pass and runs into the step cap gives 5,000 events per test: 25,000 events and a 2.6 MB trace for a 5-test problem. 03 and W0 say "every occurrence", so nothing is dropped; whoever returns traces over HTTP may want to trim.
- `run_tests` and `trace` each run the tests, so calling both runs them twice (the parse is shared). At the times below this did not seem worth a combined call.

## Contract remarks (nothing was edited outside my paths)

- `Trace` and `RunResult` cannot carry the reason for `parse_error` / `unsupported`; use `harness.check`.
- 03 §2.5 puts the unit tests in `c_interp/tests/`; they are in `tests/A1/` as 06 §2 says.
- 03 §2.5 expects 500-700 lines; `interp.py` is about 1,900 because each operator has its own closure (that is what makes it fast).
- `interp.py` raises Python's recursion limit to 20,000 at import and leaves it there: 100 nested C calls need a few thousand Python frames.
- No new pip package is needed.
