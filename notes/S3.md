## Endpoints

All object responses carry `model_version` and `latency_ms`. Errors are `{"error": "..."}` with 404/422/500 and no traceback. `GET /code-items` is a JSON list, matching the fixture and 05 §5 (see open issues).

| Endpoint | Behaviour |
|---|---|
| `POST /exam/start` `{learner_id, length?, demo?}` | `{exam_id, item, progress: {k, n}, time_limit_s: 1500}`. `demo: true` or `length <= 3` is 2 coding + 1 trace. Anything longer is the full 5 + 5. P(A) and states are copied from S1. D-classes that are still unseen start at 0.15 inside the exam session (D3). The item is `public_exam_item` (no correct answer, belief, or exposure). |
| `POST /exam/answer` `{exam_id, item_id, code?, answer?, ms, sample_runs, skipped?}` | `{logged: true, next_item \| null, progress}`. No diagnosis. A trace answer must be one of the options. `skipped: true` consumes the slot, moves Elo as a fail, and writes no class evidence (`outcome: "skip"`). |
| `POST /exam/finish` `{exam_id}` | `{report}`. One adaptivity-log row per answered item, each with its reason. |
| `POST /exam/probe` `{exam_id, probe_id, answer}` | `{report}` with findings rebuilt. A repeated probe id returns the report already stored. |
| `GET /exam/{id}/report` | The finished report, or a report of the answers so far. |
| `GET /quiz/next?learner_id=&type=&concept=` | `{item, reason}`. Public fields only. Filters are optional. Unknown learner is 404. |
| `POST /quiz/answer` `{learner_id, item_id, answer, ms}` | `{correct, correct_answer, explain, updates, ask_reason}`. `ask_reason` is true only when the chosen option is the belief answer of two or more classes. A `reasoning` item is 422 and points at `/reason`. |
| `GET /code-items?problem_id=&type=` | Public items. Never `fix`, `planted`, `bug_lines`, `explain`, `exposes`, or `op_id`. Snippet answers live in `fix.answers` and stay on the server. |
| `POST /code-items/debug` `{learner_id, item_id, line}` | `{correct, bug_lines, explain, fix, updates}`. `line: null` means "no bug". `planted: null` items do not move P(A). |
| `POST /reason` `{learner_id, ref: {kind, id}, text}` | `{status, top, reader, updates}`. |
| `POST /lab/reason` `{text, code?}` | Same shape, `updates: []`, nothing stored. |
| `GET /metrics` | Cards E1–E18 from the files that exist, plus EDA. |

`model_version` on exam routes is the newest `ml/artifacts/diagnoser_*` folder name (the model is not loaded just to read that name). Quiz is `quiz`. Code items are `code-items`. `/reason` uses T2's `model_version(result)`. `/metrics` uses the E1 card's version.

## How an exam answer is scored

Coding: S2's pipeline (`analyse` + `diagnose` with no probe answers). A gate failure, including submitting the starter (G2), is status `gate` and does not invent a class. If the diagnoser artifact is missing, pass/fail comes from the tests only, with an empty `top`. Trace: D3's `_apply` (likelihood, then `exam_trace`). The HTTP response never includes the diagnosis.

Checked separately from the suite: a Q01 body that is not the starter and not a constant return comes back `logged: true` with no diagnosis key, and the stored evidence holds the pipeline diagnosis.

The scripted test submits each item's starter (or the first trace option) and finishes. The report has three log rows, one reason each.

## How a collision is settled

`qz_m01m08_mcq_01`, answer `"8"` (belief of both M01 and M08): `ask_reason: true`, and the two classes move by the same amount.

`POST /reason` with that quiz id:

- The reader is `read(code, text, reader=None, keep=item classes)`. `reader=None` keeps T2's order: tfidf, then biencoder, then frozen. The fine-tuned model is on disk at `ml/artifacts/reason_9d7b8962/`, and it is used only when tfidf cannot load or `RELEARN_REASON_READER` names it. This suite's settled answer came from tfidf.
- Status `unsure` (below the reader's own threshold) does not change P(A) and does not change the option posterior. The threshold is not edited. E17: skipping unsure sentences costs about 0.19 accuracy on collision pairs (tfidf test 0.91 if every sentence is used, 0.72 with the rule).
- Status `matched` and `P_text(k) >= 0.6` (`TEXT_MATCH_P`) moves that one class with the 05 §4 likelihoods (0.5 vs 0.05). The option posterior is also multiplied by `apply_text` (`CORRECT_REASON` is applied as `CORRECT`). A second `/reason` on the same item does not apply that again.
- The M08 sentence "Counting starts at 1, so a[4] is the 4th number in the list." matches M08 (about 0.99) and leaves M08's P(A) above M01's.

A matched reader probability between the reader threshold (tfidf 0.584) and 0.6 updates the stored posterior only. P(A) stays put. That second cut is D2's `TEXT_MATCH_P`, not a new threshold.

## Persistence

Created on the store connection (not in `store.py`):

- `exams(exam_id, learner_id, state_json, log_json, report_json)`
- `quiz_progress(learner_id, asked_json, pending_json)` — asked ids, and the collision context for `/reason`

P(A) for a class the exam, quiz, debug item, or reason actually touched is written with `Store._read_entry` / `_write_entry` on that same connection. `reassess` is not called: it would apply a second update, and a `predict_output` reassess on an ACTIVE class starts an intervention (S1). The value written is the one D2 or D3 already computed.

`/attempt` is still S2's. It already accepts `code_item_id` and returns a `fix_bug` verdict. This package does not register that path (attempt.py loads first and wins).

## Metrics

Read, in order, so `ml/eval/cards/` wins on a duplicate id: `ml/eval/out/e-b/*_card.json`, `ml/eval/*_card.json`, `ml/eval/cards/*.json`. A file with no `E<number>` id is ignored (`E08_deepseek_answers.json`). E1–E18 are all present today. A missing id would be `{metrics: "missing", missing: true}`, not zeros.

Copied through, not recomputed: E8 baseline `macro_f1`, E15 `m_recall_on_dsa_trained_main_only` and `shortcut_auc`, E14 curves / final profile F1 / stable-recheck, E10 resolution rows, E12 `table`, EDA red-rule statuses and the row and hash counts in `docs/eda.md`.

`effective_n.unique_prog_op` and top-level `domains` are `"missing"`. The per-domain numbers stay inside the cards. `generated_at` is the newest card or `docs/eda.md` mtime.

## Decisions where the plans are silent

1. Only two exam lengths exist in `params.EXAM_LENGTH`. `demo` or `length <= 3` selects demo. Any other length is the 10-item exam, not a custom length.
2. A skipped exam item is unobserved for knowledge and still counts toward the 5+5 (or 2+1) quota. Elo treats it as a fail. The log outcome is `skip`.
3. `/exam/probe` was not implemented in D3. The answer updates P(A) with the likelihood ratio `P(answer | class)` vs `P(answer | CORRECT)` for classes in the probe's belief map, then the report is rebuilt. The first answer stands.
4. `GET /code-items` stays a list, as in the fixture. The other routes use the envelope.
5. Exam `model_version` is the artifact folder name, so `/exam/start` does not load LightGBM.

## Skipped or faked

- Not faked: quiz scores, exam selection, reader status, and metric numbers.
- Not done: applying the 05 §4 `fix_bug` knowledge update inside `POST /attempt` (S2 owns that route and only returns the verdict). `complete_snippet` remains a normal attempt. `debug_line` is `/code-items/debug`.
- The scripted exam in `tests/S3` submits starters, so those two coding items stop at the gate. The pipeline path was run once outside the suite (above) and is what a changed body hits.
- No DeepSeek call. No new packages.

## Open issues

- `POST /attempt` with a `fix_bug` id does not move P(A). S2 returns `code_item.response` of `correct` / `wrong` / `other_bug`. Wiring that into the knowledge table means either S2 calling the writer here, or I1 doing it. This package cannot edit `attempt.py`.
- `GET /code-items` has no `model_version` or `latency_ms`. 03 §11 asks for both on every response; 05 §5 and the fixture are a bare list. The list wins.
- Top-level `domains` and `effective_n.unique_prog_op` are `"missing"`. No card states `unique_prog_op`. Domain splits are inside E1 and E15, not in the 03 §9.4 `domains` shape.
- E17's unsure rule still costs about 0.19 on collision pairs. The reader threshold and `TEXT_MATCH_P` (0.6) were left as shipped.
- With `reader=None`, tfidf answers even though `ml/artifacts/reason_9d7b8962/` is present. That is T2's load order, not a fallback failure.
- S1's `seed` deletes `learners`, `knowledge`, `attempts`, and `events` only. An exam or quiz row for that learner is left behind.
- An exam session is a snapshot of P(A) at `/exam/start`. A quiz taken while that exam is open can be overwritten for a class the exam then tests, because the exam writes its own session value back.
