# D2 — Knowledge model and state machine

## Built

- `ml/learner/knowledge.py`: P(A) updates from 03 §8.2 and the knowledge half of 05 §4. `update_p(p, kind, ...)` is the dispatcher. `likelihood_ratio` is the one ratio used by a signature failure and by a matched sentence.
- `ml/learner/state_machine.py`: `next_state(state, p_active, event)` for every arrow in 03 §8.4, `reassess_conditions` in the shape of `schemas.Condition`, and the 03 §8.3 transfer-family table.
- `ml/learner/__init__.py` exports those two modules.
- `tests/D2/`: 67 tests. Every 03 §8.2 row, every 05 §4 knowledge row, every §8.4 arrow, and a near miss of each threshold.

Numbers are read from `ml.contracts.params`. A failed code task is only the likelihood ratio (exposure, or `FAIL_SIGNATURE_IF_ACTIVE` when the problem lists none, against `FAIL_SIGNATURE_IF_NOT`). There is no `max(P, posterior)` write.

## How a later package calls this

D3 can update an exam item with the same functions, then pass the new P into `next_state`:

- coding `fail_k` (caller already checked posterior ≥ `DIAGNOSIS_ACTIVE_P`): `update_p(p, "signature_failure", exposure=e_ik)`
- coding pass with `latent` equal to this class: `update_p(p, "latent_pass", exposure=e_ik)`
- coding pass, no latent: `update_p(p, "exam_code", correct=True)`
- coding failure that is not this class's signature: `update_p(p, "exam_code", correct=False)`
- exam trace: `update_p(p, "exam_trace", correct=...)`, which is the `belief_mcq` row
- UNSEEN and the new P is at least `DIAGNOSIS_ACTIVE_P`: `next_state("UNSEEN", p, exam_update=True)` → `ACTIVE`
- STABLE, exam item passed, `e_ik` at least `EXAM_MASTERY_EXPOSURE`, P under `MASTERED_P`: `next_state("STABLE", p, exam_passed=True, exposure=e_ik)` → `MASTERED`

One call applies one transition. A relapse does not also start treatment.

## Decisions where the plans are silent

1. **A zero denominator leaves P unchanged.** `P·e + (1−P)·f` is 0 when both likelihoods are 0, or when P is 0 or 1 and the remaining likelihood is 0. No other clamp. The hint cap is the `min` already in the hint formula.
2. **The reassess label stays the plan's sentence** `"Misconception probability < 0.15"`. The comparison uses `STABLE_P`. `detail` is the probability to two decimal places, as in the plan's `"0.31"`.
3. **`fix_bug` does not read `bug_lines`.** Top-1 still equal to the planted class is the "planted bug still there" case: item response wrong, not the signature rule. Top-1 is a different misconception and the posterior is at least `DIAGNOSIS_ACTIVE_P`: signature update on that class only. The planted class is left unchanged. Below the threshold, no update.
4. **`signature_failure` and `latent_pass` do not re-check the posterior.** 03 §8.2 says the caller invokes the failure update only when the posterior is at least 0.5. The `fix_bug` branch checks, because 05 §4 puts the threshold in that row.
5. **A failed `complete_snippet` does not update inside that kind.** 05 §4 says a failure is a normal diagnosis. The caller uses `signature_failure` for that. A pass uses the `same_family_code` correct row.
6. **`exam_trace` is the `belief_mcq` row.** `ITEM_GUESS_SLIP` has no separate exam-trace pair. 03 §8.2 takes that guess from §6.2, which is the value already stored on `belief_mcq`. It is not recomputed here.
7. **`predict_output_trap` is its own kind.** `predict_output` whose `belief` map contains the class being updated resolves to it and uses the trap row. `mcq` and `next_state` stay on `belief_mcq` even when the belief map names the class.
8. **Forgetting compounds once per level** (`levels`), not `P + levels·φ·(1−P)`. A negative `levels` is treated as zero.
9. **`correct_reasoning` does not move P.** The knowledge rule applies only to a match with `P_text(k)` at least `TEXT_MATCH_P`. Unsure, unmatched, or below that threshold: no update. The Bayes rewrite of the sentence posterior (`(0.02 + P_text)^0.5`) belongs to D1.
10. **Transfer families are the copied table only.** A family counts when it is in that class's list and is not the family where the misconception was found. 03 §8.3 also says a main-game class may later transfer onto a DSA family (M01 → `pairwise_check`) once Trials are open. That pair is not in the table, so `is_transfer` is false for it.
11. **`after_item` defaults to true** on probation, so a bare call with P above `RELAPSE_TO_TREATING_P` goes to TREATING. An intervention event is not an item, so it does not take that arrow. Probation never goes to ACTIVE.
12. **Starting priors are the caller's.** `POPULATION_PRIOR` and `EXAM_DSA_PRIOR` are not applied here. There is no `KnowledgeEntry` store: no evidence log, `times_seen`, or `last_tested`.
