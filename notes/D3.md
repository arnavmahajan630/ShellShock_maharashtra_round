# D3 — Exam engine and quiz selector

## Built

- `ml/exam/select.py`: pool (Q01–Q18 plus `ml/data/exam_items.json`), per-class binary expected information gain in bits (03 §8.5.4), Elo pass chance, the opening item, and the fixed blueprint (03 §8.5.7). Trace exposure is `P(belief answer | class)` from `likelihood`. Options stay in file order.
- `ml/exam/run.py`: scripted exam. A coding answer goes to an injected diagnoser. Pass, `fail_k`, and latent updates go through `update_p` (`signature_failure`, `latent_pass`, `exam_code`). A trace answer is scored with `likelihood`; P(A) then moves on the `exam_trace` row. Classes move independently. `next_state` runs after each update. The function returns only the report.
- `ml/exam/report.py`: `ExamReport` with sectors, findings, up to three deferred probes, recommendations, and an adaptivity log. Every answered item is in the log with its reason.
- `ml/quiz/select.py`: `next_item(learner_state, items, *, type=None, concept=None)` and `score_answer`. The public item has no `correct`, `belief`, or `explain`. `ask_reason` is true only when the chosen option is the belief answer of two or more classes.
- `tests/D3/`: 13 tests.

Numbers come from `ml.contracts.params`. Knowledge updates call `ml.learner.knowledge.update_p`. Transitions call `ml.learner.state_machine.next_state`.

## How a later package calls this

S3 can run an exam with `run_exam` once it has a real diagnoser, or call `select_next` one item at a time. `public_exam_item` is the client view (no exposure, no correct answer, no belief map). Quiz:

```python
public, reason = next_item(state, items, type=None, concept=None)
scored = score_answer(state, item, answer)
# scored["ask_reason"] is true only on a two-class belief collision
```

`score_answer` does not write the learner record. It returns `p_before` and `p_after`. A `predict_output` item passes `belief` and `class_id` into `update_p`, which uses the trap row when the class is in the belief map. `mcq` and `next_state` stay on the belief-MCQ row.

## Decisions where the plans are silent

1. **Blueprint ids.** 03 §8.5.7 names `xt_bsearch_1` and `xt_arr_1`. The bank uses `xt_search_*` and `xt_array_*`, and `xt_search_1` is already in the list. The strings blueprint ends with `xt_search_6`. The no-strings blueprint uses `xt_search_2` and `xt_array_1`. Both lists are 5 coding + 5 trace. Strings are dropped only when `strings=False`.
2. **Planet bonus.** The plan says +100 if all 3 planets are complete. `classes.PLANETS` has five names. The bonus is applied when `planets_complete=True`, or when `completed_planets` contains every name in `PLANETS`.
3. **Sector prior EIG** for item 1 is the highest item EIG among that sector's difficulty-1 coding items. The item inside the winning sector is then chosen by the full score. Ties use a hash of `(learner_id, exam_id, label)`.
4. **Quiz score is EIG only.** 05 §5 says the same information gain without the exam's composition rules. Coverage, the pass-rate penalty, the ghost bonus, quotas, and the opening-item rule are exam-only. A reasoning item has no options, so its gain is zero unless the caller filters to that type.
5. **Finding words that do not fit.** §8.5.6 has NEW, RELAPSED, HELD, UNCERTAIN, NOT_TESTED. HELD means `next_state` returned MASTERED. NEW means the class was tested, it started UNSEEN or at P ≤ 0.3, and the updated P is at least 0.5. A tested class that stays under 0.3 and is not MASTERED or RELAPSED has no status, so it is omitted. A class that was already active with P > 0.7 and stays there is omitted for the same reason. NOT_TESTED is every class with no evidence. The 0.3 and 0.7 cutoffs are the plan's words; they are not in `params.py`.
6. **Unanswered items.** A short script stops the exam. Those items are not in the log and do not move P or Elo. `ExamReport` has no sentence field for the timeout; `items_answered` is the signal.
7. **Constraints are hard.** If no remaining item can satisfy the quotas, the coding cap, consecutive sectors, and coverage (when the length allows it), the exam stops early. Demo and full runs in the tests do not hit that case.
8. **Deferred probes** use `expected_information_gain` on a simplex built from P(A), not a diagnosis posterior. A probe is kept only when its gain is at least `EIG_MIN_BITS`, and at most three are returned. `for_class` is the uncertain class in that probe's belief map with the highest P(A).
9. **Recommendations** are two problems from `TRANSFER_FAMILIES` that were not administered, DSA files first, then main. Fewer than two are returned when the catalog runs out.
