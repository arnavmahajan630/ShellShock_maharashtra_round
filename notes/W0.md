## Decisions made where 03 and 05 are silent

Each of these is also written next to the code it affects.

1. **`ml/contracts/params.py`** collects every hand-set number of 03 §5.5, §6, §8 and 05 §4 in one place.
2. **Effects are strings** `"<name>:<field>:<field>"`; field order is in `subset.EFFECT_FIELDS` (e.g. `call:factorial:2:3`, `write_cell:1:7`).
3. **Steps:** one per finished statement; a for-header gives a step for its init, each test and each update. `vars` holds scalars of the current frame; no value yet = `null`; arrays are not in `vars`.
4. **`call` / `ret` effects** sit on the callee's first step and on its return step.
5. **`trace.events`** lists every occurrence over all tests, each with a `test` index. `loop_iters`, `branch` and `effects_count` are **sums over all tests**; `max_depth` is the maximum. `trace.per_test` holds each test's own `{status, returned, printed, loop_iters, branch, effects_count, max_depth}` in test order (03 §2.4). Features that say "on every test" read `per_test`. (The example in 03 §2.4 shows one test's numbers on the sums, plus one `per_test` entry.)
6. **Feature `a_has_array_write`** was added: 03 §4.1b masks D03/D04 on "an array write" but names no feature for it. `MASK_PRECONDITIONS` in `feature_names.py` is the masking table.
7. **`RunResult`** (what `run_tests` returns) = `{status, backend, tests}`.
8. **Public problem** keeps `predict_item.correct` (the app needs it for the reveal) and drops `belief`.
9. **Learner object** inner fields (`KnowledgeEntry`, `nodes`, `attempts`) follow the 02 D09 star card.
10. **Trap items** (`items.json`) use the probe shape plus `target`.
11. **`Problem.one_pass`**: optional reference single-pass helper for sorts (needed by `r_eq_one_pass`).
12. **CORS** allows all origins, not only localhost: the phone reaches the laptop by its network address.
13. **`GET /_routes`** (not in the contract) lists which endpoints are live and which are fixtures.
14. **Fixtures that depend on the request** use `{"_by": field, "cases": {...}, "default": key}`; see `server/READY.md`.
15. **Group F is offline.** `FEATURES` is groups A, B, R, C. `OFFLINE_FEATURES` is group F, computed after the model for the top-3 classes (03 §4.4).
16. **Main loop** is the loop with the most iterations on the display test; ties go to the outermost. Reference features use `correct_variants[0]` (03 §4.1). Nested loops add `a_outer_*` and `a_inner_*`.
17. **`op_variant` equals `op_id`.** E3 holds out one operator per class.
18. **`CLASS_DEFINING_FEATURES`** is the per-class signature list. E6 strict drops it; EDA 10.5 and the evidence templates read it.
19. **One knowledge update** for a failed code task: likelihood ratio with `e_ik` (default 0.5) vs 0.03. No `max(P, posterior)`. `π_L(CORRECT)` and `π_L(OTHER)` are 1.0. A passing attempt whose top class is not CORRECT is `status: "correct"` with `latent` (03 §5.5, §6.1, §8.2).
