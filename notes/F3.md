# F3 — Feature assembly and evidence sentences

## Built

- `ml/features/extract.py`
  - `extract(problem, code, trace=None, reference_trace=None, run_reference=None, *, run_result=None, static_main_loop=False) -> (row, meta)`.
    - `row`: numpy float64, length 149, in `FEATURES` order (A 93, B 35, R 16, C 5).
    - `meta`: `features` (name → value, same order), `lines`, `values` (placeholders per feature), `parse_ok`, `entry`, `loops`, `has_trace`, `tests` (`{passed, total}` or None).
    - No trace → groups B and R are NaN, A and C are filled. Code that does not parse → group A is NaN too, the row still has 149 columns.
    - Runs nothing: traces and the reference runner are arguments. The reference's main loop and "is it recursive" come from parsing `correct_variants[0]` (cached).
  - `task_features(problem)`: group C from the signature (`t_has_array_param`, `t_returns_float`, `t_is_void`, `t_has_char_array_param`) and from the tests (`t_mutates_array_arg` = some test expects `array0`; with no tests: void function with an array parameter).
  - `parse_signature`, `TEMPLATE_FIELDS` (placeholders `extract` can supply per feature), `OPTIONAL_FIELDS`.
  - `load_templates()`, `sentence_key(entry, value, features)`, `render_evidence(feature, meta)`: turn one feature of an extracted row into `{"type", "text", "line", "feature"}` or None. M1's `evidence.py` calls this and adds the weight.
- `ml/features/evidence_templates.json`: 142 feature entries + `f_fix` (the fixer sentence, not a model feature). Every feature in `CLASS_DEFINING_FEATURES` has an entry. Group C and `a_max_nesting`, `a_char_array_param` have none on purpose (task shape is not evidence).
- `tests/F3/`: 31 tests.

## Template file format

```json
"feature": {"type": "CODE|RUN",
            "text": "used when the value is not 0",
            "positive": "…", "negative": "…",     // win over text when the value is above / below 0
            "zero": "used when the value is exactly 0",
            "<key>_fallback": "used when a placeholder of <key> is missing or empty",
            "neutral": 1,                          // a value that says nothing: no sentence
            "requires": ["a_has_recursion"],       // other features that must be non-zero
            "variants": [{"if": {"a_base_case_present": 0}, "text": "…"}]}
```

A sentence is never half-filled: if a placeholder is missing and there is no fallback, `render_evidence` returns None and the evidence generator moves to the next contributor. The sentences 03 §5.6 gives as examples are used word for word. The combined `b_depth_cap` + `a_base_case_present = 0` sentence is a variant of `b_depth_cap`.

## Decisions

1. **Extra keyword arguments on `extract`.** The five positional arguments are the ones in the package brief. `run_result` (the learner's `run_tests` result) is needed for the final arrays of in-place problems (see notes/F2.md, observation 1). `static_main_loop=True` picks the main loop without the trace, so a training row can match what an AST-only request gets (notes/F1.md, observation 1).
2. **`r_eq_top_frame_only` is switched off when the reference does not recurse**; `extract` decides that from the reference code.
3. **`meta["values"]["r_eq_top_frame_only"]`** borrows `fn`, `arg`, `line` from `a_rec_call_discarded` when the code has the discarded call, so the plan's sentence ("the result of `f(n - 1)` was thrown away (line 3)") can be filled; otherwise a fallback sentence is used.
4. **Evidence for a value of 0** exists only where absence is the signal: `a_update_present`, `a_update_var_is_cond_var`, `a_base_case_present`, `a_base_case_static_reachable`, `b_base_return_executed`, `a_reads_all_params`, `a_n_nested_loops`, `b_pass_frac`. The loop ones require a loop, the recursion ones require recursion.

## Not exact / known limits

- Expressions in sentences are reprinted by `pycparser.c_generator`, which adds brackets: the learner's `fuel * 100.0 / cap` is shown as `(fuel * 100.0) / cap`, `a[n - 1 - i]` as `a[(n - 1) - i]`.
- `_REFERENCE_CACHE` is a module-level dict (cleared at 512 entries); fine for a server process, not shared between workers.
- `meta["values"]` for group R shows the first failing test where the relation held, not all of them.

## Checked only on fixtures — recheck when A1 / B1 / B2 exist

- Group C is tested on the three fixture problems and on hand-written signatures. `parse_signature` assumes one-line C signatures of the kind in 03 §3.3.
- The exact-row test uses the `p03_le_oob_read` fixture and W0's simulation of the correct loop as the reference trace.
- The "every applicable sentence can be filled" test runs `extract` on 75 snippets without traces and 17 traced cases built in the test; it reaches every template except `f_fix`. It has not been run on generator output.
- Nothing here has been run with a real `run_reference` built from `ml.runner`.
