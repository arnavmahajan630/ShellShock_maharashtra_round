# C3 — Dataset generator

## Built

- `ml/generate/registry.py` routes `sites`, `apply` and `holds` to C1 or C2. DSA op ids, including `amb_pair_bound`, `m08_mirror`, `m01_half_bound`, `m02_pointer_stuck` and `m10_print_bool`, use `holds_dsa`. `op_variant` equals `op_id`. U1 and U2 are skipped.
- `ml/generate/augment.py`: the nine style edits from 03 §3.5.2, plus CORRECT near-miss rewrites from §3.5.3.
- `ml/generate/verify.py`: interpreter `run_tests` / `trace`, cached by reprinted AST. Class rows must fail a test and `holds(op_id)`. OTHER must fail a test and match no class predicate. CORRECT must pass every test. A step-cap timeout is a failed test.
- `ml/generate/ambiguity.py`: normalised AST hash. Groups whose labels are exactly `{M01, M08}` become source `AMB` with soft labels 0.5/0.5 (one row per label). Any other clash is printed and the minority label is dropped.
- `ml/generate/build_dataset.py` writes `ml/data/dataset.jsonl` and `ml/data/passes_by_luck.jsonl`. `ml/generate/card.py` writes `docs/dataset_card.md`.
- `tests/C3/test_dataset.py`. `pytest tests/C3`: 1 passed.

## Caps versus the aim

The default cap is 15 rows per `(problem, op_id)` and 6 augmentations per `(problem, variant, op_id)`. M01, M08, OTHER and most of CORRECT stay inside it (M01 526, M08 550, OTHER 587, CORRECT 1381, AMB 454, near-miss share 65%).

Classes with few bank sites cannot reach 250–550 rows at that cap, so the cap is raised and rows are still round-robin across problems and operators. The pool, not the ceiling, is what stops these short of the aim:

## Drop rates

Operator drop rate is on the unaugmented mutant. Luck and “OTHER matched a class predicate” both count as drops. Kept rows still passed verify. C3 does not edit C1/C2.

Above 40%: `amb_le_array` 57% (13 of 23 pass by luck), `oth_swap_operands` 60%, `oth_wrong_var` 68%, `oth_flip_branch_rel` 74%, `oth_drop_stmt` 53%. The OTHER drops are the §3.5.4 rule that an accidental class instance is not OTHER. 95 augmented copies were rejected on re-verification.

Zero kept rows:

- `m02_update_in_branch`, `m04_int_literal`, `m06_while_assign` — no site on a matching correct variant (same finding as notes/C1.md).
- `d08_array_eq` — no site in the bank (notes/C2.md).

## Passes by luck

49 rows in `ml/data/passes_by_luck.jsonl`, not in `dataset.jsonl`. `amb_pair_bound` on Q11 cv1 and cv2 is in that file: the extra iteration writes `a[n - 1]` and the saved `first` overwrites it, so every test passes (notes/C2.md). The trace still records `oob_read`.

## Clashes (printed, not soft-labelled)

All four are the two orders of one two-bug pair, which normalise to the same tree but take different primary labels. The minority label was dropped.

- `{M04, M10}` on P13: `m04_cast_late` with `m10_printf_noreturn`, and with `m10_printf_return0`.
- `{D01, M02}` on Q12: `m02_pointer_stuck` with `d01_else_return`.
- `{D05, D07}` on Q16: `d05_drop_base` with `d07_discard`.

## Two-bug

Bounded sample: at most 2 compositions per variant, at most 8 attempts, both predicates required, and the composed code must fail a test that each single mutant also fails. 149 rows kept (source E). That is about 2% of the file, not 8%. Raising it would mostly add more order-pair clashes like the four above, so the bound stays.

## Skipped

- Near-misses that were too brittle to emit: accumulator-parameter recursion, a `found` flag plus `break`, `else continue`, and a bubble `swapped` early-exit.
- Feature-dropout rows (NaN trace groups) are a training step, not a column of this file.
- Weird-but-valid extras that did land: `x = x + 0`, an unused one-cell array, debug `printf` with the return left in place.
- Trace-only DSA checks from §3.5.4 rule 6 (single-pass equality, multiset change) are not extra drop rules. D07/D08 events are stored on `trace_summary` when the interpreter emits them. Keep is fail-a-test plus `holds`, plus the odd-`n` filter for `d05_unreachable_base`.

## Not faked

Counts, hashes and the luck pool come from the interpreter on the bank. No new packages were installed.
