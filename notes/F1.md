# F1 — AST features (group A)

## Built

- `ml/features/ast_feats.py`: `ast_features(code, entry=None, trace=None, display_test=0) -> (feats, meta)`.
  - `feats`: exactly the 93 names of `GROUP_A`, in contract order, floats.
  - `meta["lines"]` / `meta["values"]`: line and sentence values of the first place each flag fired (03 §5.6 `feature_lines`). For a few features whose *absence* is the evidence (`a_update_present`, `a_update_var_is_cond_var`, `a_base_case_present`, `a_base_case_static_reachable`, `a_reads_all_params`) the place is reported even when the value is 0.
  - `meta["loops"]`: main / outer / inner loop lines, the main loop's variable and condition variables. F2 needs these to read `loop_iters` and the window variables.
  - `strip_source`, `parse`: local clean-up (comments to spaces, `#include` and other `#` lines blanked, `#define NAME literal` substituted outside literals, smart quotes). Line numbers do not move. `ml.c_interp` is not imported.
- `tests/F1/`: 75 parseable snippets with the full non-zero feature set of each (`expected.py`), plus hand-written near-miss, contrast, one-hot, main-loop, metadata and clean-up tests.

## Rules chosen where 03 §4.1 is silent (also in the module docstring)

1. **Main loop.** With a trace: most iterations in `trace["per_test"][display_test]["loop_iters"]`, ties to the outermost, then first in source. **Without a trace: the first outermost loop.** For nested loops these can differ (the inner loop usually iterates more), so the `a_main_*`, `a_bound_form_*`, `a_init_form_*`, `a_update_*` columns of a no-trace row can differ from the same code's row with a trace. See "Contract observations" 1.
2. **A learner-written `main` is ignored** when the file has any other function. Everything else is analysed (helpers included); `a_return_const_only` and `a_reads_all_params` look at the entry function only.
3. **Flags are 0/1** ("present anywhere"). Counts: `a_n_loops`, `a_max_nesting`, `a_n_nested_loops` (loops at depth ≥ 2), `a_n_self_calls`. `a_update_dir` is −1/0/+1 and is 0 when the only step is on a variable the condition does not test.
4. **Update structure.** An update is a constant step on any variable, or any change of a condition variable. `a_update_in_branch` = a condition variable is changed, but not on every path through the body (an `if`/`else` that both step, or a branch that returns/breaks, counts as every path). So the correct two-pointer loop is 0 and the "one pointer stuck" form is 1.
5. **Index shapes.** `a_index_i` = index is a loop variable or any scalar the function changes (`a[mid]`, `a[min]`); `a_index_n` = an unchanged name (`a[n]`). An unchanged local stands for its initialiser (`int last = n - 1; a[last]` → `a_index_n_minus_1`).
6. **`a_array_loop_start1` / `a_array_loop_le_n`** need the body to index with the bare loop variable, so `for (i = 1; i <= n; i++) s += a[i - 1];` lights neither.
7. **`a_return_in_loop_else`**: an `if … else` inside a loop, not part of an `else if` chain, whose else branch directly holds a `return`. The chain rule keeps `… else return mid;` of a three-way binary search at 0. **`a_assign_in_loop_else`**: the same variable is plainly assigned in both branches.
8. **`a_base_case_static_reachable`**: base condition compares a parameter with a constant (or another name) and every self-call moves toward it: `n-1` with `<=`, `<`, `==`; `n-2` with `<=`, `<` or two adjacent `==` bases; `n/c` with `<=`, `<` or `== 0`; `n+1` with `>=`, `>` or `==` against a name. A base condition the rule cannot read counts as reachable unless the argument is unchanged.
9. **`a_int_div_into_float`**: an `int / int` whose value reaches a float variable, float return, float cast or float expression (static typing from declarations). **`a_float_literal_in_div`**: a `/` with a float literal in either operand (`* 100.0 / cap` counts).
10. **`a_single_loop_with_swap`**: at least one loop, none nested, and a swap (with or without temp) anywhere.

## Skipped / not exact

- `a_param_written` (M09, Strong) is not in `GROUP_A`; not built.
- Scoping is by name within a function (no block scopes). A shadowing declaration is treated as the same variable.
- `a_decl_noinit_read_first` uses source order as an approximation of "some path".
- Mutual recursion is not detected (only direct self-calls).
- Two loops on the same source line share one `L<line>` key; the main-loop choice cannot tell them apart.

## Contract observations (nothing in `ml/contracts/` was edited)

1. **Static vs trace main loop.** Group A is not trace-dependent by contract (`TRACE_DEPENDENT_GROUPS = ["B", "R"]`), but the main-loop rule needs iteration counts. Training rows are built with a trace, serving rows without one fall back to the static rule. If AST-only serving matters (E9 "AST-only", ITSP), the cleaner fix is to build the dropout rows' group A with `trace=None` too. F3 exposes this as a parameter; M1's loader decides.
2. **The pair-bound twin is invisible to group A when the outer loop is the main loop.** `for (j = 0; j < n; j++)` with `a[j + 1]` differs from the correct `j < n - 1` only in the inner loop's bound, and the contract has `a_outer_bound_*` but no `a_inner_bound_*`. With a trace the inner loop is normally the main loop and `a_bound_form_n` shows it.
3. **`a_single_loop_with_swap` is 1 for a correct `reverse`** (one loop, one swap). It is listed as D04-defining; the model has to combine it with `a_half_bound` / `a_index_pair_plus1`.
4. **`a_array_loop_start1` is 1 for the correct max loop** (`best = s[0]; for (i = 1; …)`), as the definition says. It separates from M08 only together with `a_index_const0`.
