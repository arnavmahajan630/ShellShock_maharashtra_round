# G1 — the gate

## Built

- `server/app/gate.py`
  - `check(problem, code) -> {"code", "message"}` (`schemas.Gate`); `gate` is the same function under a second name.
  - `normalise(code)`: the G8 fix (smart quotes, long dashes, odd spaces, full-width ASCII, CRLF). The gate works on `normalise(code)`. A caller that passes the code on to the interpreter can pass `normalise(code)` too.
  - `strip_comments(code)`, `preprocess(code)`: comments to spaces (line numbers kept), `#include` blanked, `#define NAME value` substituted.
  - Needs only `pycparser` and `ml/contracts/subset.py`. It imports neither `ml.c_interp` nor `ml.oracle`, and executes nothing.
- `tests/G1/test_gate.py`: 145 tests. At least one positive and one negative case per code, on P03, P11, Q17.

## Order of the checks

G8 normalise → G1 empty → G7 size → G2 same as starter → G3c C++ → G4 for a `#` line outside the subset → parse (on failure: G3b Python, else G3a) → G4b forbidden builtin → G4 unsupported construct → G5 entry signature → G5b no recursion → G6 constant answer → G0.

## Decisions (where 03 §3.7.1 is silent)

| Code | Decision |
|---|---|
| G1 | Empty after normalising and stripping comments. `None` counts as empty. |
| G2 | Same token sequence as `problem["starter"]` once comments and whitespace are removed. |
| G3a | The line and a short reason, e.g. `Core rejected line 2: missing `;`.` Reasons: `missing `;``, `missing `)``, `missing `}``, `unmatched `}``, `unterminated string`, `unterminated comment`, `illegal character `@``, `unknown type `bool``, `incomplete expression`, `unexpected `<``, `this is not a C function`, `could not be read as C`. pycparser 3.0 gives no position for some errors ("Invalid expression", "At end of input") and raises a bare `AssertionError` for an extra `}`; the gate then finds the line itself (brace count, or the first line whose removal lets the file parse, with a 150 ms budget). For "missing `;`" the line reported is the line that lacks it, not the next one. |
| G3b | Only when the file does **not** parse as C, and it has `def f(...):`, `elif`, a `:`-then-indent block, `for x in`, an `import` line, or `print(` with no `;` and no `{` anywhere. So C code with a helper called `print` is not called Python. |
| G3c | Checked before parsing, because `cout << n;` is valid C syntax. Signals outside comments and strings: `cout`, `cin`, `endl`, `std::`, `::`, `using namespace`, `class X {`, `template <`, `new T(`, or an include of `<iostream>`, `<bits/stdc++.h>`, `<vector>`, `<string>` and similar. |
| G4 | The message names the construct with the words of `subset.REJECTED`. When a file has several, the most telling one wins: scanf, malloc, `<string.h>`, struct, switch, goto, multi-dim arrays, pointers, `&x`. `union` and `.`/`->` count as `struct`. |
| G4, extra | Things outside 03 §2.1 that have no entry in `REJECTED` are also G4, named in the message: `sizeof`, `typedef`, `enum`, a `#` line other than `#include` / `#define NAME value` (e.g. `#ifdef`, `#define with arguments`), and a call to any function that is neither defined in the file nor a builtin (e.g. `abs()`). |
| G4b | A call to a name in `problem["forbid"]`. The contract message is written for `strlen`; for another forbidden name the word is replaced. Checked before G4. |
| G5 | The entry function (name and number of parameters taken from `problem["signature"]`) must be **defined** in the file with that many parameters. Parameter names, types and the return type are not compared. A prototype alone is G5. |
| G5b | Only for `problem["sector"] == "recursion"`. Passes if some function reachable from the entry function calls itself, directly or through a cycle; so a recursive helper called by the entry function is accepted. A recursive function that is never called is not. |
| G6 | The entry function has parameters, never reads any of them, and has a `return <value>` or a `printf`. A statement `n = 5;` is a write, not a read. An assignment used as a value (`if (code = 42)`) **is** a read, so the M06 program is not gated. A function with no return value and no printf is not G6. Logged on `relearn.gate` at INFO. |
| G7 | More than 120 lines or more than 4,096 UTF-8 bytes of the code as submitted. Exactly 120 lines / 4,096 bytes pass. Checked before parsing. |
| G8 | Not a code: the gate reports G0. Non-ASCII text inside comments and string literals is left alone; a non-ASCII identifier is a G3a. |

Not a gate (03 §3.7.1 last row): wrong programs, endless loops, division by zero, missing base cases. `tests/G1` has 8 such programs that must return G0.

## Checked beyond the tests

- All 66 C-defined programs of `tests/A3/cases.py` come back G0, all 9 rejected-construct samples of `tests/A3` come back G4, and the 15 wrong-but-valid programs of `tests/A3/test_sample_problems.py` come back G0 except the loop-only factorial, which is G5b as intended. This was a one-off run, not a committed test (it would tie `tests/G1` to `tests/A3`).
- Speed: about 0.3 ms per call on a sample-problem solution; a 120-line file with a position-less parse error took about 150 ms (the scan budget).

## Problems found in the contracts

- 03 §13 K6 says "8 gate fixtures behave as specified" but no such fixtures exist in `tests/fixtures/` or `server/fixtures/`. `GATE_FIXTURES` in `tests/G1/test_gate.py` (13 named cases, one per code) stands in for them.
- `GATE_MESSAGES["G4b"]` has the builtin name fixed in the text (`strlen`); there is no `{name}` placeholder.
- The G6 row counts "returns/prints a constant". A hard-coded `fire(); fire(); fire();` (world effects, no return or printf) is not covered by that wording and is not gated.
- No sample problem has a non-empty `forbid`, so the G4b tests use a Q13-shaped dict built in the test file.

## Skipped / still faked

- Nothing is faked. The gate is not wired into any route: `/run`, `/attempt` and `/lab/diagnose` belong to package S2.
- The gate does not check that the code stays inside the subset in every detail (for example bitwise operators or a global variable pass the gate). The interpreter's `unsupported` status is the second line of defence; S2 has to handle it.
