# X1 — public data slices

All of this is for evaluation only (05 §8). Nothing downloaded and nothing derived from a download is committed: the repo holds the scripts and the tests.

## Built

| File | What it does |
|---|---|
| `ml/external/common.py` | Size check before download (GitHub API for repositories, HTTP HEAD for files), capped streaming download, safe unpacking, `fetch_log.json`. Standard library only. |
| `ml/external/itsp.py` | 03 §3.4 "X (ITSP) protocol" steps 1–3: fetch, pair `*_buggy.c` / `*_correct.c`, keep one-hunk pairs, map the hunk to a candidate class, write `ml/data/itsp_slice.jsonl` in the `schemas.DatasetRow` shape, print counts per class. |
| `ml/external/codeflaws.py` | Fetch the Codeflaws archive, unpack only the C sources, `load()` the buggy / fixed pairs. |
| `ml/external/introclass.py` | Fetch IntroClass, `load()` the student program versions. |
| `ml/external/mohler.py` | Fetch the Mohler / Texas short answers (v2.0), `load()` answers with their 0–5 scores. |
| `ml/external/fetch_all.py` | Runs all four; `--sizes` only reports sizes; `--only`, `--target`, `--max-mb`. |
| `tests/X1/` | 53 tests. No network: sizes and downloads are faked, loaders run on small trees built by the tests. Four tests look at the real downloads and are skipped where nothing has been fetched. |

Commands:

```
python -m ml.external.fetch_all            # all four sources; prints sizes first, then counts
python -m ml.external.fetch_all --sizes    # sizes only, downloads nothing
python -m ml.external.itsp --no-fetch      # relabel from what is on disk
```

## Where the data is

The target folder is a parameter (`--target`, or `RELEARN_EXTERNAL_DIR`). Its default is `ml/data/external/` of the **main checkout**: when the code runs inside a git worktree under `<main>/.claude/worktrees/`, it still writes to `<main>/ml/data/external/`. On this laptop that is `C:\Users\harsh\hacks\bitnbuild\ml\data\external\` (gitignored).

The limit is **3 GB per source** (raised from 500 MB by the coordinator during the run). A source over the limit is skipped and the skip is written to `fetch_log.json`. No source came near the limit, so nothing was skipped.

Total on disk: 318 MB.

Things that did not go as the size check predicted, recorded as they happened:

- **IntroClass was much larger than reported.** The GitHub API figure (154.8 MB) is the packed repository. The snapshot zip was 296 MB and unpacked to **1,890 MB**, of which 1,867 MB were 66,543 repair-tool `.log` files. Those logs were deleted right after unpacking (23.2 MB left) and the fetcher now leaves `.log` files out when unpacking. It stayed under the 3 GB limit throughout, but the pre-download figure was wrong by a factor of 12. The same applies to any GitHub source: the API figure is a lower bound, and the cap on the download itself is the real guard.
- **Codeflaws is unpacked only in part.** The archive holds 407,746 files (1.39 GB unpacked, mostly test inputs and outputs). Only the 7,808 `.c` files (5.9 MB) are unpacked; the archive is kept so `python -m ml.external.codeflaws --all` can unpack the tests later without downloading again.
- **First ITSP attempt failed** with `WinError 5 Access is denied` when renaming the freshly unpacked folder (a Windows lock on a new folder). The rename is now retried; the second attempt worked. Both attempts are in `fetch_log.json`.
- **Python could not verify the umich.edu certificate** for Mohler (`CERTIFICATE_VERIFY_FAILED: unable to get local issuer certificate`; the server does not send its intermediate certificate). The fetcher falls back to `curl` for that case. Verification is never switched off.
- **ITSP is fetched as a zip snapshot, not with `git clone`** as 03 §3.4 step 1 says. Same files, no history, no git needed. The commit is recorded in the log.
- **Counts differ slightly from the plans:** Codeflaws has 3,904 pairs with both sources present (05 §8 says 3,902; the archive has 3,908 folders). Mohler has 2,442 answers over 87 questions, which includes the questions the authors themselves leave out of their published work (lines starting with `#` in `data/docs/files`); `load()` does not filter them.

## ITSP slice

`python -m ml.external.itsp` on the 661 pairs:

| | |
|---|---|
| kept (one hunk, at most 3 removed and 3 added lines) | **396** |
| dropped: more than one hunk | 94 |
| dropped: hunk longer than 3 lines | 139 |
| dropped: identical once whitespace is ignored | 32 |

Candidate labels of the 396 kept pairs:

| Label | Count |
|---|---|
| OTHER | 377 |
| M01 (M01/M08 twin, soft label 0.5 / 0.5) | 7 |
| M06 | 3 |
| D07 | 3 |
| M07 | 2 |
| D05 | 2 |
| M03 | 1 |
| M05 | 1 |

No pair matched the rules for M02, M04, M10, D01, D02, D03 or D08.

**These are candidates, not labels.** Step 4 of the protocol (a human hand-check of 40–80 items, dropping unclear ones) has not been done. Every row has `rater2_label: null`. To make the check quick, `<target>/itsp_slice_review.tsv` lists each row with its rule, the removed and added lines and an empty `human_label` column. Only 19 of the 396 rows carry a class other than OTHER, so the hand-check should start with those 19 and then sample OTHER (some OTHER rows look like classes the literal rules do not reach, for example an added `sum = 0;` or `if (n >= 0)` → `if (n > 0)`).

How the rows are filled (`schemas.DatasetRow`):

- `source: "X"`, `split: "holdout_problem"`, `problem_id: "ITSP-<problem id>"`, `family: "itsp_lab<N>"`, `author: "itsp:<Lab>/<problem>/<program id>"`.
- `code`: the buggy program, without the verdict comment ITSP puts at the top of each file.
- `verified.tests_failed` / `tests_total`: from that verdict comment (`numPass`, `numTotal`). `verified.predicate`: `["itsp_rule:<rule name>"]`.
- `label` / `soft_label` / `labels_all` / `ambiguous_group`: the M01/M08 twin gets `label: "M01"`, `soft_label: {"M01": 0.5, "M08": 0.5}`.
- `ast_hash`: a hash of the code without whitespace and comments. It is **not** the generator's AST hash: these are whole programs with `scanf`, which the project's parser does not accept.
- `op_id`, `variant`, `trace_summary`: null.

Decisions where the protocol is not exact:

- **"One hunk"** is taken as `difflib.unified_diff` defines it (3 lines of context: changes that close together are one hunk). This is what lets "accumulator init moved out of the loop" be a single hunk. **"≤ 3 lines"** is at most 3 removed and at most 3 added lines (`--max-lines`).
- The diff ignores whitespace and blank lines, and the verdict comment at the top of each file is removed first (it always differs).
- Rules are tried in the order 03 §3.4 lists them; the first match wins. `<=` ↔ `<` counts in both directions and only in a `for` / `while` header. For M06, a debug `printf` deleted in the same hunk is ignored. "Added `i++`" means the added text is the removed text plus exactly one increment statement. D05 and D07 need the enclosing function to call itself.

## Not committed, and one thing to decide

- `ml/data/itsp_slice.jsonl` is written by the script but **not committed**, although 06 lists it under X1's "Owns". It contains ITSP student code, and the instruction for this package and 05 §8 both say the data is not to be committed or redistributed. It is also not in `.gitignore` (a root file X1 may not edit), so `git status` shows it as untracked after a run. A copy is kept at `<target>/itsp_slice.jsonl` so it survives the removal of a worktree. **Suggested:** add `ml/data/itsp_slice.jsonl` to `.gitignore`.
- **The plans say ITSP has no licence; the repository has a `LICENSE` file with the MIT licence** (the GitHub API also reports MIT). 03 §3.4 and 05 §8 could be corrected. The slice is still left uncommitted here, as instructed.
