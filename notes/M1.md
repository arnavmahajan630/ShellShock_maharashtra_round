# M1 — The diagnoser model

## Built (`ml/model/`)

| File | What it does |
|---|---|
| `data.py` | `TrainData`; `load_npz` (a ready matrix); `load_dataset` (`dataset.jsonl` → filter per 03 §5.3 → features via `extract` → cached `features_<hash>.npz` next to the dataset); `build_matrix`; soft labels as weighted duplicates (`expand_soft`, `class_weights`); seeded 15% feature dropout |
| `train.py` | folds, inner early-stopping split, the 12-config grid, final OOF, refit, calibration, novelty thresholds, artifact; `python -m ml.model.train [--data … --out … --no-grid --max-rounds N]` |
| `calibrate.py` | scalar temperature on OOF logits (`minimize_scalar`, bounds [0.5, 5]); ECE (10 equal-width bins), NLL, Brier, reliability table, before and after |
| `novelty.py` | kNN space over standardised A+B+R (NaN → median, constant columns dropped, ≤ 4,000 reference rows, float32); OOF distances; `tau_d` (99th percentile); `tau_p` (≥ 90% precision on accepted OOF predictions); `assess` → the `novelty` object; `exclude=` for E6 "LOCO strict" |
| `mask.py` | structural masking from `MASK_PRECONDITIONS`; the same function scores OOF predictions in training and serves requests |
| `predict.py` | `Diagnoser.load(folder)` / `.latest(root)`; `.proba(X)` (temperature, then mask), `.novelty(x)`, `.contributions(x)`, `.knn_distance(X)` |
| `decide.py` | 03 §5.5; takes the posterior plus `fix_check(top1, top2)` and `best_probe(posterior)` callables; returns the 03 §11.1 diagnosis object without evidence |
| `evidence.py` | `pred_contrib` slice for the top class → top-3 positive contributors that have a sentence → items; one RUN summary; fixer sentence; Bayes items; HARD-twin sentence |
| `baselines.py` | majority; rules in the fixed order of 03 §5.7; TF-IDF (char 3–5) + logistic regression; TF-IDF + LightGBM; `run_baselines(data, folds)` on the diagnoser's folds |

`tests/M1/`: 112 tests. Artifacts in tests go to a pytest temp folder; nothing is written to `ml/artifacts/`.

## How the pieces are meant to be wired (for S2)

```python
row, meta = extract(problem, code, trace, reference_trace, run_reference, run_result=run_result)
model = Diagnoser.latest()                       # ml/artifacts/diagnoser_<sha8>/
p_code = model.proba(row)[0]                     # calibrated, masked
novelty = model.novelty(row, p_code)
posterior = bayes_layer(model.posterior_dict(p_code), …)          # package D1
diagnosis = decide(posterior, gate_code=…, tests_passed=…, novelty=novelty,
                   fix_check=…, best_probe=…, probes_asked=…, model_version=model.model_version)
diagnosis["evidence"] = build_evidence(model.contributions(row), diagnosis["top"][0]["id"], meta,
                                       status=diagnosis["status"], twin_set=diagnosis["twin_set"],
                                       fix_desc=…, extra_items=bayes_items)
```

## Result on the made-up matrix — proof that the code runs, nothing more

`tests/fixtures/features_synth.npz` is random 0/1 noise with one telltale column per class (W0). **These numbers say nothing about real accuracy.**

| | no grid (default config) | 12-config grid |
|---|---|---|
| model | `diagnoser_448a9e9f` | `diagnoser_8313d449` |
| grouped-CV macro-F1 (5 folds, masked) | 0.308 ± 0.024 | 0.322 ± 0.026 |
| OOF macro-F1 / accuracy, masked | 0.310 / 0.362 | 0.323 / 0.378 |
| OOF macro-F1 / accuracy, unmasked | 0.463 / 0.465 | 0.471 / 0.472 |
| temperature | 0.929 | 0.963 |
| ECE before → after | 0.062 → 0.078 | 0.065 → 0.080 |
| NLL before → after | 1.3372 → 1.3328 | 1.3765 → 1.3752 |
| tau_p / tau_d | 0.95 / 16.2 | 0.95 / 16.2 |
| baselines (macro-F1) | majority 0.005, rules 0.036 | TF-IDF skipped: the matrix has no source text |

Why the numbers look the way they do:
- The telltale column is on for 90% of its class and each of the other 18 is on 8% of the time, so about 0.47 is the best any model can do. The unmasked score is at that ceiling.
- **Masking lowers the score here** because the precondition columns (`a_has_recursion`, `a_mid_like_var`, …) are random noise in this matrix: the true class of most D02–D08 rows gets masked out. On real data a D05 row always has recursion, so this effect does not exist there.
- `tau_p` = 0.95 (the top of the grid) because no confidence threshold reaches 90% precision on noise; nearly every row would abstain.
- ECE gets slightly worse after temperature scaling. T minimises NLL (which does go down), not ECE.

Timings for one training run on this matrix (1,900 rows × 149 columns, `num_threads=4`), end to end including calibration, novelty and saving:
- default config, no grid (5 early-stopped fold models + 5 fold refits + final model): **3.0 s** (2.96 s and 3.04 s on two quiet runs);
- full 12-config grid (71 LightGBM fits): **29 s** quiet;
- the final fit alone: 0.4 s; calibration + novelty thresholds: 0.13–0.5 s;
- other agents were running on the laptop at the same time: the same runs took 15 s and 41 s under load.
Training is reproducible: the same data gives the same `sha8` on every run.

## Decisions where 03 is silent or the brief and 03 differ

1. **`StratifiedGroupKFold`, not `GroupKFold`.** 03 §5.3 says to stratify by domain and not to use `GroupKFold`. Folds are grouped by problem and stratified by `TrainData.domain` (main / dsa, from the problem's `sector`). A matrix without a domain (the made-up one) is split by problem only.
2. **Early stopping and OOF.** Each fold's training part is split again by problem (1/4 for early stopping). During the grid the early-stopped model predicts the fold. For the chosen config the training part is refitted whole for that number of rounds before predicting, so the OOF logits used for temperature, `tau_p` and E1 come from models trained on as much data as CV allows. The final model uses `ceil(mean of the folds' best rounds)`.
3. **Macro-F1** is over the classes present in the scored rows; a prediction that names either label of a soft-labelled row counts as correct. Log-loss uses the soft targets.
4. **Masking in selection.** The grid is scored on masked predictions (03 §4.1b). Masking after temperature and masking before give the same argmax, so the choice does not depend on T.
5. **`meta.json` holds the kNN reference matrix** as base64 float32 (03 §5.3 lists it under meta.json). 1,900 rows → 1.5 MB; 4,000 rows → about 3 MB.
6. **`sha8`** is the first 8 hex digits of SHA-256 of `model.txt`.
7. **Dropout rows** in `build_matrix` are extracted with no trace at all, so their group A uses the static main-loop rule, exactly like an AST-only request (notes/F1.md, observation 1).
8. **`training_rows`** keeps sources A, E, AMB only (03 §9.1 TRAIN), drops `holdout_problem` and passes-by-luck rows.
9. **`decide`**: `top` = best class plus runner-up (dropped below 0.02). `twin_set` is set when the top two share a twin set and either the call is close (p1 < 0.75 and p1 − p2 < 0.25) or a probe was already asked; this reproduces W0's fixtures (T1 kept after the probe, no twin set for a clear M07 with M06 far behind). `latent` needs p ≥ 0.5 (03 §5.5; kept as `LATENT_MIN_P` in `decide.py` because `params.py` has no name for it). `two_bug` is only tried when both top classes are misconceptions.
10. **Evidence `weight`** = the feature's share of all positive contributions toward the class (0–1). The fixtures show values like 0.9 / 0.7; if the app expects "relative to the strongest", divide by the first item's weight.
11. **Evidence skips** a contributor whose feature has no sentence for its current value (for example a task-meta column, or a flag that is 0) and takes the next one, so fewer than three items can come back.
12. **Rules baseline** uses the extracted features (group A, plus B and R when present), not the generator's predicates (packages C1/C2). When the generator lands, E-a may prefer its predicates; the priority order is the same.

## Faked or only checked on fixtures — recheck when the dataset and interpreter exist

- **Every score above is on the made-up matrix.** No real row has been through the model.
- `load_dataset` / `build_matrix` are tested with a fake backend (fixture traces for two P03 programs). The real path needs `ml.runner.trace`, `ml.runner.run_tests`, and problem files in `ml/problems/main` and `ml/problems/dsa`. `python -m ml.model.train` with no arguments stops with a message until `ml/data/dataset.jsonl` exists.
- The claim "well under a minute on ~9k rows" (03 §5.2) is not checked: 12 configs took 29 s on 1,900 rows. Expect a few minutes on 9k rows, or use `--no-grid` while iterating.
- TF-IDF baselines ran on a 30-snippet corpus only.
- The rules baseline is tested on hand-written snippets without traces; it has never been scored against labelled data.
- Evidence with real extractor metadata is tested on one program (the P03 `<=` fixture) and with hand-set contributions. With the model trained on noise, which features come out on top is meaningless.
- `decide` is tested with stub `fix_check` / `best_probe`; the Bayes layer (D1) and fixer (R1) are not in the chain.
- Novelty thresholds were only exercised on noise: `tau_p` hit the top of its grid. On real data check that `accepted_share` in meta.json is sensible.
- `ml/artifacts/diagnoser_*` is **not** in `.gitignore` (only `reason_*` is). Decide in I1 whether artifacts are committed.
