# F2 — Trace and output-relation features (groups B and R)

## Built

- `ml/features/trace_feats.py`
  - `trace_features(trace, reference_trace=None, problem=None, *, loops=None, ref_loops=None, run_result=None) -> (feats, meta)`: the 35 names of `GROUP_B`.
  - `collect_outputs(problem, trace, run_result=None)`: one record per test (`status, returned, printed, array0, effects_count, max_depth, passed`). Shared with group R.
  - `check_passed`, `values_equal`, `is_garbage`, `loops_from_trace` (fallback when no AST information is passed).
- `ml/features/relation_feats.py`
  - `relation_features(problem, outputs, run_reference=None, *, recursive=None) -> (feats, meta)`: the 16 names of `GROUP_R`.
  - `make_run_reference(problem, run_tests, code=None)`: builds the `run_reference(args)` callable from a `run_tests(problem, code)` backend (for example `ml.runner.run_tests`), with a cache, and attaches `.one_pass` when the problem has a `one_pass` helper. Nothing is called at import time; the feature function itself never touches a backend.
- `ml/features/ast_feats.py` (small addition): `meta["loops"]["inline"]` = loops whose body starts on the header line, which `b_body_once_vs_many` needs.
- `tests/F2/`: 57 tests. Exact full-group values on the three fixture traces, hand-built traces (validated against `schemas.Trace`) for every event the fixtures lack, and group R against pure-Python reference functions.

No trace → every B and R feature is NaN. Reference missing → only the features that need it are NaN.

## Value conventions (03 §4.2–4.3 leave them open; also in the module docstrings)

| Feature | Rule |
|---|---|
| event features (`b_step_cap`, `b_uninit_read`, `b_oob_*`, `b_intdiv_*`, `b_empty_body_exec`, `b_assign_in_cond_rt`, `b_missing_return`, `b_depth_cap`, `b_discarded_call_value`, `b_str_literal_compare`, `b_array_compare`) | 1 if the event occurred on any test |
| `b_pass_frac` | `run_result` passed/total when given; else per-test check of `expect` (returned ±1e-3, printed, array0, effect counts, `max_depth_le`) |
| `b_iter_delta_mean` | mean over tests of learner − reference main-loop iterations. **Not clipped**: a timed-out loop gives about +2,500 |
| `b_iter_delta_const_pm1` | +1 on every test, or −1 on every test (read from `per_test`) |
| `b_return_first_iter` | fraction of the tests where the reference iterated ≥ 2 on which the learner finished with exactly 1 iteration |
| `b_branch_always` / `b_branch_never` | some learner `if` was evaluated ≥ 2 times with one outcome only, while some reference `if` took both outcomes |
| `b_printed_eq_ref_return` | fraction of tests where the printed text (stripped) equals the reference's return value; 0 for problems that return nothing |
| `b_returned_garbage`, `r_is_garbage` | value within 1,000,000 of `GARBAGE` (garbage plus a sum is still garbage) |
| `b_body_once_vs_many` | display test: no body line ran twice, and the reference's main loop iterated ≥ 2 |
| `b_window_frozen` | display test: the main loop's condition variables are identical on two consecutive passes (consecutive header-line steps count as one pass) |
| `b_rec_arg_constant` / `b_rec_arg_growing` | display test: two consecutive frames with identical arguments / some numeric argument strictly larger in every consecutive frame pair (≥ 2 pairs) |
| `b_base_return_executed` | display test: some frame returned without calling deeper (or the test ended `ok` with no `ret` effect at all, for void functions) |
| `b_max_depth_ratio` | trace `max_depth` ÷ reference `max_depth` |
| `b_multiset_changed` | in-place problems: final array is not a permutation of the input on some test; 0 for other problems |
| `b_sorted_frac` | in-place problems: mean share of adjacent pairs in order in the final array; **NaN for other problems** |
| `b_n_outer_passes_ratio` | learner outer-loop iterations ÷ reference outer-loop iterations, summed over tests; a learner with one loop counts one pass per test; **NaN when the reference has no nested loop** |
| group R | fraction of **failing** tests on which the relation holds; 0 when nothing fails |

Group R input changes: the sequence is the first list/string argument and its size parameter is the int after it equal to its length. Drops and "only" runs need ≥ 2 elements. `n_minus_1` uses the size parameter on the same sequence, or any one int argument when there is no sequence; `n_plus_1` is only tried without a sequence. `first_check_only` tries the first element, the first two and the two ends; `last_check_only` tries the last element and the last two, and accepts an index result shifted back to its real position. `top_frame_only` = result equals an int argument, the last element, or the last digit of a single int argument, and is switched off when the caller says the reference is not recursive. `reversed_twice` = final array equals the input. `shift_without_wrap` = `a[1:] + [a[-1]]` or `a[1:] + [a[1]]`.

## Contract observations (nothing in `ml/contracts/` was edited)

1. **`per_test` has no final array.** `schemas.PerTest` is `{status, returned, printed, loop_iters, branch, effects_count, max_depth}`. `b_multiset_changed`, `b_sorted_frac`, `b_pass_frac` on in-place problems, `r_eq_one_pass`, `r_eq_reversed_twice` and `r_eq_shift_without_wrap` need argument 0 after the call. Worked around by taking it from the learner's `run_tests` result (`tests.results[i].got.array0`), passed as `run_result`. Without it, only the display test's array is rebuilt from `write_cell` effects, so those features see one test. An extra `per_test[i]["array0"]` is read if the interpreter ever adds it. **The caller (F3 → S2, training loader) must pass `run_result`.**
2. **`write_cell` effects do not name the array.** The rebuild assumes they refer to argument 0.
3. **Three features read the recorded steps**, which exist for the display test only: `b_window_frozen`, `b_rec_arg_*`, `b_base_return_executed`, `b_body_once_vs_many`. An unreachable base case that only shows on odd `n` is invisible to `b_base_return_executed` when the display test has even `n`; `b_depth_cap` still fires.
4. **`r_eq_top_frame_only` cannot be computed by an input change** for a product (`factorial`'s own contribution is `n`, which is not the reference's output on any input). It is implemented as a direct comparison with the arguments, as listed above.
5. **`Problem.one_pass`** has no stated function name. `make_run_reference` assumes the helper defines the problem's entry function (same signature), because that is what a backend calls. B2 should author it that way.
6. **`r_eq_first_check_only` ⊇ `r_eq_ref_first_only`** and the same for last: the single-element run is one of the candidates. They only differ when the first check involves two cells.
7. **Coincidences are part of group R.** On a 3-element array "drop first" and "last two" are the same run; on `[2, 4, 6]` "drop last" equals "last only" (2 + 4 = 6). The tests pin these down so they are not mistaken for bugs. Boolean outputs match about half of all counterfactual runs by chance.

## Checked only on fixtures — recheck when A1 and the dataset exist

- Every trace used here is W0's hand simulation or a dict built in the tests. Nothing has run through the real interpreter. In particular:
  - **Step layout**: `b_window_frozen` and `b_body_once_vs_many` rely on W0 decision 3 (a for-header records init, each test and each update on the header line; one step per finished statement). If A1 records steps differently these two change.
  - **`call` / `ret` effect text** (`call:<fn>:<depth>:<args joined by ",">`) drives the recursion features; a void function that emits no `ret` is handled, one that does is also fine.
  - **Event fields** follow `subset.EVENT_FIELDS`; `depth_cap_hit.last_args` is read as a list.
- `make_run_reference` is tested with a fake `run_tests`; the assumption that a backend returns the same `got` keys as the `expect` it is given must be checked against A1/A2.
- The reference trace for P03 in the tests is W0's simulation of the correct loop, not a fixture file.
