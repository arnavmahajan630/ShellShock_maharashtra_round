# T1 — DeepSeek client and reason sentences (+ the cloud training script from T2)

Built in the main checkout on 2026-10-04, ahead of lane 9, so the cloud fine-tuning can run in parallel.

## Built

- `ml/text/llm_client.py`: DeepSeek calls with JSON output, retries, parallel calls, and every response saved under `ml/data/llm_raw/<job>/`. A rerun reads from disk and costs nothing.
- `ml/text/prompts/contexts.json`: 102 question contexts, 6 per mistake type, each with the wrong answer a believer gives and the correct one, plus one correct-rule line per type.
- `ml/text/gen_reasons.py`: one call per (type, context, voice); filters; split by context; writes `ml/data/reasons.jsonl` and `ml/data/reasons_bundle.json`.
- `ml/data/reasons.jsonl`: **3,307 sentences**, 18 labels. Per mistake type about 120 train / 30 val / 30 test from 6 contexts (4 / 1 / 1). `CORRECT_REASON`: 255 from 17 contexts.
- `ml/text/kaggle_train.py` and `ml/text/colab_train.ipynb` (these belong to T2; built here because the human Colab run can start now).
- `tests/T1/`.

## Decisions

1. **Hidden reasoning is switched off** in the client (`thinking: disabled`). Measured on one call: about 150 output tokens instead of about 2,000, 1.5 s, no visible loss for this kind of writing. Pass `thinking=True` for jobs that need it.
2. **Model name:** the API accepts `deepseek-flash` and `deepseek-v4-pro`. The run used `deepseek-flash`.
3. **Descriptions** (what a sentence is matched against) are `"<subtitle>. Wrong belief: <belief>"` from `ml/contracts/classes.py`, not the ship name: the ship names are game fiction and carry no meaning for a text model. They are stored in the bundle and again in the trained artifact, so training and serving always agree.
4. **Contexts are hand-written**, not taken from the item bank (B3, B4 are not built yet). Context 1 of each type is its trap item (03 §8.3); the probe contexts of 03 §6.3 are included. When B4 lands, its items can be added as further contexts.
5. **Splits:** contexts 1–4 of a type are train, 5 is val, 6 is test, so val and test contexts are never seen in training.
6. **"Repeats the description" filter** drops a sentence only when 80% of its words overlap the belief text. A stricter filter would remove the most natural sentences ("variables start at 0").
7. **`CORRECT_REASON`** uses one context per type (rotating through context numbers) and three voices.

## Cost

663 calls, 182,816 input tokens, 98,035 output tokens (the first 12 calls ran with hidden reasoning on and account for about a quarter of the output). At the third-party-reported price for `deepseek-flash` that is about $0.17.

## Not verified

- Belief answers in `contexts.json` were worked out by hand, not run through the interpreter. They are prompts for the generator, not items served to learners.
- Sentence quality was checked by reading a sample, not measured. All sentences are LLM-written; real student sentences are still needed for the test set (05 §7).
- A sentence often explains the arithmetic of its own question ("6 minus 2 is 4") without showing the belief. The reader sees the sentence alone, so some of these cannot be classified by anyone; the "unsure" threshold is there for them.

## LLM-written stand-ins for the two human jobs (added later on 2026-10-04)

The team could not hand-write the realistic programs or collect classmates' sentences, so both are replaced by LLM-written sets. **Neither may be reported as hand-written, blind-authored or real student data.** The Lab Report cards that use them must say "LLM-written stand-in".

### `ml/data/realistic_llm.jsonl` — 58 student-style programs (source `R-llm`)

- Made by `ml/text/gen_realistic_llm.py`: `deepseek-v4-pro` (hidden reasoning on) role-plays a student with a given wrong belief and a messy personal style. It sees the belief text only, never the mutation rules.
- **Run check:** each program is run through the interpreter against a reference solution on a few inputs. A "wrong" program is kept only if it differs somewhere; a "correct" one only if it never differs. Without hidden reasoning, 3 of the first 6 drafts were in fact correct programs, which is why the check exists.
- **Kept 58 of 60.** Dropped after three drafts: M05 on Q09, and the hard twin on Q01 (`i <= n` in a linear search reads one cell too far but returns the right answer, so nothing shows).
- **Final labels:** 32 single-belief programs (17 classes; M05 and D01 have one each, the rest two), 3 hard twins (soft M01/M08), 10 correct-but-unusual, 7 OTHER, 6 junk for the gate.
- **Rater 2** (`deepseek-flash`, from the code alone) agreed with the intended label on 52 of 58 (kappa 0.89). Of the 6 disagreements: 4 are junk items the rater does not recognise as junk; RL-009 is a real M05 the rater missed (uninitialised loop counter); RL-019 was relabelled from D01 to OTHER (see `ADJUDICATED` in the generator). `realistic_llm_meta.json` keeps the kind, persona, the author's note and any relabelling per item.
- **Limits:** the run check shows a program is wrong, not that it is wrong for the intended reason. The reference solutions and inputs live in the generator, not in the problem bank; recheck against the real tests once B1 and B2 land. `ast_hash` is a placeholder (hash of the text), not the normalised hash of 03 §3.5.5. `ml/contracts/schemas.py` gained the source value `R-llm`.

### `ml/data/reasons_persona.jsonl` — 270 role-played "why" sentences (test only)

- Made by `ml/text/gen_persona_reasons.py`: a different model (`deepseek-v4-pro`) and a different prompt from the training sentences. One student per call, given a character and a belief, picks between two options and types why. Only the val and test contexts are used.
- **In 107 of 204 wrong-belief calls the model picked the correct option anyway.** Those were repeated with the option named; such rows have a voice ending in `_told`.
- 12 sentences per mistake type (11 for D02) and 67 `CORRECT_REASON`.

### Leave-one-class-out (run on Colab, T4, 722 s for 17 retrains)

For each mistake type the reader was trained without any of its sentences and then asked to find them from the description alone.

| | Top-1 | Top-3 |
|---|---|---|
| Mean over 17 classes | 0.120 | 0.283 |
| Best (D02) | 0.311 | 0.600 |
| Worst (M01, M07) | 0.000 | 0.017 / 0.067 |

Per class top-1: M01 0.000, M02 0.067, M03 0.106, M04 0.217, M05 0.155, M06 0.011, M07 0.000, M08 0.044, M10 0.272, D01 0.144, D02 0.311, D03 0.250, D04 0.267, D05 0.011, D06 0.011, D07 0.139, D08 0.028.

**The claim "add a mistake by writing its description, no retraining" does not hold for this reader.** Fine-tuning pulls sentences toward the 17 descriptions it trained on; a description it never trained with attracts almost nothing. For comparison, the unchanged model's nearest description scored 0.49 on the test split with no training at all. Not measured: the unchanged model per held-out class.

With equal accuracy to `tfidf`, a confidence threshold that does not hold on the persona set, and this result, the fine-tuned reader has no measured advantage. `tfidf` is the default reader.
