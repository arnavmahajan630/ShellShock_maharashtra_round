## How the server uses it (for S3)

```python
from ml.text.serve import read, top_classes, model_version
result = read(code, text)                 # code may be None
response = {"status": result["status"], "top": top_classes(result), "reader": result["reader"],
            "updates": [...], "model_version": model_version(result), "latency_ms": ...}
```

- `result["probs"]` is one probability per label in `REASON_LABELS` order; `P_text(k)` of 05 §4 is `result["probs"][REASON_LABELS.index(k)]`.
- `status` is `unsure` when the top probability is under the reader's threshold, `correct_reasoning` when the top label is `CORRECT_REASON`, else `matched`.
- `top_classes` gives at most 3 entries `{id, name, subtitle, p, band}`, best first, runners-up under 0.02 dropped. It is `[]` when no reader is loaded.
- Nothing is loaded at import. The first `read` loads the reader; call `read(None, "warm up")` at start-up if the first request should not pay for it.
- `read` never raises. Any failure inside gives `reader: "none"`, `status: "unsure"`, equal probabilities.

## Readers and order

Order: `tfidf` → `biencoder` → `frozen` → `none`. **This is the project lead's decision and differs from the text of 05 §6** (fine-tuned → frozen → word-count). Reason: on held-out contexts the word-count and fine-tuned readers are level (0.72), frozen is behind (0.60), and the fine-tuned reader's threshold did not hold on the second test set.

- The `reader` argument, or the environment variable `RELEARN_REASON_READER`, names one reader (`tfidf`, `biencoder`, `frozen`, `none`). The argument wins over the variable.
- A reader that cannot load is skipped without a message. A load is tried once per process; `serve.reset()` forgets it.

| Reader | Needs | Threshold | Where the threshold comes from |
|---|---|---|---|
| `tfidf` | `ml/text/heads/tfidf.*` (committed) | 0.584 | val split: answers 47%, 90.0% right |
| `biencoder` | `ml/artifacts/reason_<id>/` (not in git, 436 MB) | 0.871 | the artifact's `meta.json` (val split on Colab) |
| `frozen` | `ml/text/heads/frozen.*` (committed) and `BAAI/bge-base-en-v1.5` `onnx/model.onnx` in the Hugging Face cache (436 MB) | 0.585 | val split: answers 46%, 90.5% right |

All three thresholds use one rule (the one in `kaggle_train.py`): the smallest confidence at which accepted validation answers are at least 90% right, with at least 10 accepted.

## Decisions where the plans are silent

1. **Heads are stored as plain arrays, not fitted at load and not pickled.** Measured for the word-count reader: fitting takes 2.6–4.0 s (four runs); loading the stored arrays takes 15 ms. The stored file is 1.43 MB (26,559 features × 18 labels, float32). Stored arrays also make the threshold belong to exactly the predictor that is served. The rebuilt reader matches the fitted pipeline's probabilities to within 1e-4 (checked at fit time and in a test), and reproduces the T1 table numbers exactly.
2. **The word-count reader does its own tf-idf and logistic step.** Counting uses scikit-learn's `CountVectorizer` with a fixed vocabulary; the weighting (1 + log tf, × idf, L2 per block) and the softmax are numpy. So the head does not depend on how scikit-learn stores a fitted model.
3. **`frozen` at serve time never touches the network** (`local_files_only=True`). Only `python -m ml.text.fit_heads` downloads. The head records the model revision it was fitted with (`a5beb1e3…`) and loads that revision.
4. **Masking only on whole, self-contained code.** The code must parse as C with at least one function, and must not call a function it does not define (`printf` and a few other library calls are allowed). Otherwise there is no masking. Reasons, both measured:
   - Most quiz snippets are bare statements. Wrapping them in an empty function so they parse was tried and dropped: it removed the true class on 10 of the 85 train and val contexts (`low = mid;` alone has no mid computation; a swap of two plain variables has no array write; a one-line sort that calls `swap(...)` has no array write).
   - One test context (`D04_c6`) is a whole function that calls a `swap` helper it does not show. Masking it removed D03 and D04 and took the word-count reader's test accuracy from 0.720 to 0.664. With the "calls nothing it does not define" rule no context of either sentence set loses its own label (a test checks all of them).
5. **`keep=`**: labels that must never be masked. S3 can pass a quiz item's own `classes`.
6. **The threshold is applied after masking.** It was chosen on unmasked validation sentences. With the val rows' code passed in: answers 49%, 89.6% right (119 of 553 val rows have usable code).
7. **A named reader that cannot load falls through to the normal order**, it does not give `none`. The response says which reader answered.
8. **Empty sentence** → `unsure` with equal probabilities, without calling the reader. **Long input** is cut to 2,000 characters.
9. **`CORRECT_REASON` display text** is `name: "Correct reasoning"`, `subtitle: null`. `CLASS_INFO` has no entry for it.
10. **When no validation rows exist** (the 60-row sample), `fit_heads` uses 0.6 (`TEXT_MATCH_P`) and writes that it is a default.
11. **`data_sha256` in a head** is taken over the file with Windows line endings folded, so it is the same on every checkout. A test fails if `reasons.jsonl` changes without a refit.
12. `check_readers.py` was left as it is. A test compares its pipeline with the stored head.

## Done-when check

- `read()` works with `tfidf` and with `frozen` on the 60-row sample. `frozen` is tested twice: with a small fake embedder (always runs), and with the real model, fitted on the sample's 48 training sentences (runs only when the model is in the Hugging Face cache).
- The same call uses `biencoder` when the artifact folder is present and skips it when the folder is empty. Tested with a fake artifact (always runs) and with the real one (runs only when it is there).
- Tests that need the big files skip when the files are absent.

## Not verified, or not exact

- **`frozen` ran on the real model here**, but through the ONNX file that the Hugging Face repo ships, not through PyTorch. It scores 0.633 on val and 0.603 on test; the Colab run (PyTorch) reported 0.637 and 0.605. That is 2 and 1 sentences. The cause was not chased (there is no torch here to compare vectors). The unchanged model's nearest-description score on the test split is the same as on Colab (0.490).
- The download needs network access once. On a machine without it, `frozen` is skipped and nothing else changes.
- Latency was measured while other jobs were using the CPU. A quiet machine should be faster.
- Hindi in Devanagari, emoji and control characters are tested only for "does not raise", not for a sensible answer.
- No real student sentence has been through any reader.

## Found in other packages (not changed)

- **D03 and D04 masking assumes arrays** (`MASK_PRECONDITIONS` → `a_has_array_write`). A swap of two plain variables, or a sort that calls a `swap` helper defined elsewhere, has no array write, so both classes are masked. For the diagnoser this matters if a problem supplies a helper outside the learner's code. For the reader it matters if a quiz item shows such code inside a whole function: pass `keep=item["classes"]`.
- **D02 masking needs a mid computation in the code** (`a_mid_like_var`). A snippet that only shows `low = mid;` would lose D02 if it were masked.
- `ml/external/common.default_target()` points at the main checkout when run from a worktree, so `ml.external.mohler.load()` reads the main checkout's copy. E16 looks in its own checkout first.
